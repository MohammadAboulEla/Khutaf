# Khutaf — AI Agent Guide

Khutaf is strictly a Windows desktop real-time in-game Arabic translator (Wails v2 + WebView2, currently focused on Unity Mono and IL2CPP games). **Khutaf will never be a web app** — do not introduce web-app, HTTP-server UI, or SSR abstractions.

## Build, Test & Verify Commands

Match `.github/workflows/ci.yml` and `scripts/build-native.ps1`:

- **Go (Windows full suite):**
  - `go vet ./...`
  - `go test -race -count=1 ./...`
- **Go (Linux cross-check subset — no Windows-only packages):**
  - `go vet ./internal/arabic ./internal/config ./internal/hook ./internal/pipeline ./internal/translator/...`
  - `go test -race -count=1 ./internal/arabic ./internal/config ./internal/hook ./internal/pipeline ./internal/translator/...`
- **Rust (native hook & wire protocol):**
  - `cargo test --manifest-path native/Cargo.toml`
  - `cargo clippy --manifest-path native/Cargo.toml --all-targets -- -D warnings`
  - Build & stage `runtime/khutaf-hook64.dll`: `powershell -ExecutionPolicy Bypass -File scripts/build-native.ps1`
- **Frontend (Vue 3 / Vite):**
  - `npm --prefix frontend test` (Node `node --test src` unit & i18n parity tests)
  - `npm --prefix frontend run build`
- **Full Wails App Build:**
  - `wails build -ldflags "-X main.AppVersion=<version>"`

## Critical Cross-Layer Invariants

1. **Dual Wire Protocol Sync:** `native/khutaf-proto/src/lib.rs` and `internal/hook/proto.go` implement the exact same binary wire protocol (`PROTO_VERSION = 2`) and share golden-byte test vectors (`internal/hook/proto_test.go`). Any frame or `Settings` change must update both sides in lockstep and rebuild `runtime/khutaf-hook64.dll`.
2. **Backward-Compatible Unity Hook IDs:** Hook IDs `1..=14` (`HOOK_TMP_SET_TEXT` through `HOOK_FEBUCCI_TEXTANIMATOR_SET_TEXT`) and `caller_rel_ctx` RVA matching in `native/khutaf-hook/src/unity/mod.rs` identify saved hooks in `games.json`. Never renumber existing IDs; append new IDs starting at `15`.
3. **Version Alignment:** `AppVersion` in `app.go` and `[workspace.package].version` in `native/Cargo.toml` must stay identical and match the GitHub release tag `v<version>` for in-app updates.
4. **Secrets & Diagnostics:** `LLMSettings.APIKey` is encrypted at rest using Windows DPAPI (`dpapi:` prefix in `internal/config/dpapi_windows.go`). Never log plaintext API keys; diagnostic exports go through `sanitizeConfigForExport` / `redactString` in `internal/session/telemetry.go`.
5. **Windows Build Tags & Linux CI:** Root app files (`app*.go`, `tray_windows.go`), `internal/session/*`, `internal/hotkeys/hotkeys_windows.go`, `internal/updater/apply_windows.go`, `internal/pipeline/cache_sqlite_windows.go`, and `internal/config/dpapi_windows.go` carry `//go:build windows`. Keep shared packages (`arabic`, `config`, `hook`, `pipeline`, `translator/...`) compiling on Linux.
6. **Generated Bindings & Release Assets:** Never hand-edit `frontend/wailsjs/` (regenerated by Wails). Never bundle `runtime/TMP_Font_AssetBundles/` into release zips (downloaded on demand with SHA-256 verification).
